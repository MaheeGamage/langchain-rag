Stage Details
🔍  Stage 1 — Walker

Recursively discovers files under DATA_ROOT, filters by extension and hidden status, returns a deterministically sorted List[Path].

ConfigDefault
skip_hiddenTrue
skip_extensions.rst .json .csv .pack .idx .rev .sample
Output sorted for reproducible runs.
📄  Stage 2 — Parser

Routes each file to a format-specific parser; detects source_corpus from path keywords.

ExtensionParserGranularity
.md .mdx parse_mdx 1 doc / file
.ipynb parse_notebook 1 doc / cell
.pdf parse_pdf 1 doc / page
.py parse_python AST nodes + docstrings
Corpus detection (path substring → label)
mlflow qiskit qprov sample-quantum-circuit → sample unknown
✂️  Stage 3 — Chunker (Strategy Pattern)

Routes each Document to a specialised chunking strategy. Priority order (first match wins):

P1
doc.metadata["doc_type"] is set
→ Explicit override
P2
content_type == "code"
→ CodeChunkingStrategy
P3
corpus in {"paper", "orig_paper"}
→ PaperChunkingStrategy
P4
filename contains synthetic keywords
→ SyntheticDocChunkingStrategy
P5
fallback
→ NarrativeChunkingStrategy
Narrative
Pass 1: MarkdownHeaderTextSplitter on H1/H2/H3
Pass 2: RecursiveCharacterTextSplitter if section > chunk_size
Adds section, h1/h2/h3 metadata
Code
Pass-through if ≤ chunk_size
Otherwise: split on \ndef / \nclass boundaries
Preserves whole functions/classes
Paper
Finds abstract section
Prepends abstract to every other chunk
Adds abstract_prefixed: True metadata
Fallback → Narrative if no abstract
Synthetic
Sliding window with 20% overlap
Higher overlap preserves cross-domain context
Used for bridge / taxonomy docs
🧠  Stage 4 — Embedder

Batch-embeds chunks and upserts to ChromaDB with MD5-based deduplication and per-document error recovery.

FeatureDetail
Deduplicationmd5(content) → skip seen IDs
Batch sizeBATCH_SIZE = 25
Error recoverybatch fail → retry per-doc
Collectionnamed from embedding model
TransportHTTP / HTTPS ChromaDB client
Supported providers
ollama openai gemini
Output: { added, skipped, failed }
